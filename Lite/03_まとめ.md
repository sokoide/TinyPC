# 03 まとめ

## 起動経路

```text
CPU Reset
  → SeaBIOS
  → ディスクLBA 0を0x7C00へロードして実行
      ├─ INT 10h: "Booting..."
      ├─ INT 13h: CHS 0/0/2を0000:8000へ1セクタ読む
      └─ 0000:8000へfar jump
          └─ INT 10h: "Hello from Stage 2!"
```

## 自分で説明する

- BIOSがブートセクタに要求するサイズ、ロード位置、署名は何か。
- Stage 2はディスクのどこに置かれ、どのアドレスで実行されるか。
- `INT 10h`と`INT 13h`がそれぞれ担う仕事は何か。
- 起動ドライブ番号`DL`を保存してからINT 13hへ渡すのはなぜか。
- Stage 2の`org 0x8000`とfar jump `0000:8000`はどう対応するか。

ここで扱うのはブートチェーンであり、IVT内部、スタックの詳しい動作、BSS、Cの`main`は対象外である。

## 答え合わせ

1. この教材のフロッピー起動では先頭512バイトを物理アドレス`0x7C00`へ読み、末尾2バイトを`55 AA`とする。プログラムとデータに使えるのは署名を除く510バイト。
2. Stage 2はLBA 1（CHS 0/0/2）に置き、Stage 1が`0x8000`へ読み込む。ディスク上の番号とRAMのアドレスは別物。
3. INT 10hのAH=0Ehは1文字出力、INT 13hのAH=02hはセクタ読み込み。BIOSが用意したサービスを呼ぶ。
4. 起動した媒体と同じドライブを読むため、BIOSから渡されたDLを保存して使う。
5. `org`はラベルの値を計算するための前提、far jumpはCPUの実行先を変える命令。読み込み先も含めて配置を一致させる必要がある。

最後に「SeaBIOS → Stage 1 → Stage 2」の矢印それぞれに、**誰が・ディスクのどこから・RAMのどこへ読み・どこへ実行を移すか**を書ければ、この講義の到達目標を満たす。

## 技術的な前提と参照資料

この実装は、リアルモードのBIOSサービスと1.44MBの仮想フロッピーを前提とする。ディスク読込みの再試行、ファイルシステム、実PCへのインストールは扱わない。

- [NASM公式マニュアル：binとORG](https://www.nasm.us/doc/nasm09.html) — `org`とバイナリ出力の意味。
- [SeaBIOS公式ソース：boot.c](https://github.com/coreboot/seabios/blob/master/src/boot.c) — `boot_disk`による先頭セクタ読込みと、`call_boot_entry`による制御移譲。フロッピーの署名検査には設定依存の例外があるため、署名を消せば必ず起動に失敗するとは限らない。
- [SeaBIOS：実行フェーズ](https://qemu.googlesource.com/seabios/+/refs/tags/rel-1.17.0/docs/Execution_and_code_flow.md) — 初期化からブート処理へ進む流れ。
