# 01 Boot SectorとHello World

SeaBIOSはブート可能な媒体の先頭セクタを`0x7C00`へ読み込み、ブートセクタへ制御を渡す。この教材では末尾に署名`0xAA55`（バイト列`55 AA`）を置く。まずはBIOSの画面出力サービスINT 10hを呼び、512バイトのブートセクタから文字列を表示する。

`bits 16`は16ビットコードをアセンブルする指定、`org 0x7C00`はラベルのアドレス計算の基準である。`0000:7C00`は物理アドレス`0x7C00`を指す。セグメント方式の詳細は本編[[../01_8086とリアルモードの基礎]]を参照。

## boot.asm

第1章では、空の作業ディレクトリに次の内容を`boot.asm`として保存する。配布実装の[boot.asm](../impl/lite/boot.asm)は第2章まで完成した版なので、この段階では上書きに使わない。

```asm
bits 16                       ; NASMに16ビット用の機械語を生成させる指定（CPUへの命令ではない）
org 0x7C00                    ; RAMの0x7C00に配置される前提でラベルの値を計算する

start:
    cli                       ; マスク可能な外部割り込みを禁止する（INT命令は禁止されない）
    mov ax, 0                 ; AXに0を入れる
    mov ss, ax                ; SS=0。スタックのセグメント基準を物理アドレス0にする
    mov sp, 0x7C00            ; スタックの初期位置。PUSHやINTで使用する領域はここから下へ伸びる
    mov ds, ax                ; DS=0。文字列や変数の物理アドレスはDS×16+オフセットで求める
    mov si, message           ; SIに表示文字列の先頭位置を入れ、DS:SIで先頭の文字を指す
.next:
    mov al, [si]              ; DS:SIが指す1バイトをALへ読む
    inc si                    ; SIを1増やし、次の文字を指す
    cmp al, 0                 ; ALを文字列終端の0と比較する。ALの値は変えない
    je .halt                  ; AL=0（文字列終端）なら表示を終え、停止処理へ移る
    mov ah, 0x0E              ; BIOS画面出力の機能番号。ALに入っている1文字を出力する
    mov bx, 0x0007            ; BH=0で表示ページ0。BL=7はグラフィックスモード用で、ここでは使われない
    int 0x10                  ; BIOSの画面処理を呼ぶ。AH=0EhなのでALの1文字を表示する
    jmp .next                 ; 次の文字を読み出すため、文字列処理ループの先頭へ戻る
.halt:
    hlt                       ; CPUを待機させる。QEMUの終了命令ではない
    jmp .halt                 ; 待機から復帰した場合も、HLTへ戻って待機を繰り返す

message db 'Booting...', 13, 10, 0 ; 文字列、復帰(13)、改行(10)、表示ループ用の終端(0)を並べる
times 510-($-$$) db 0         ; 現在までの長さ($-$$)を510バイトから引き、残りを0で埋める
dw 0xAA55                     ; 署名を2バイトで配置する。リトルエンディアンなので順序は55 AA
```

### 基本動作が見える命令を使う

この例では、一つずつ動作を追いやすくするため、あえて`xor ax, ax`や`lodsb`のような命令を使わず、シンプルに記述している。`mov ax, 0`はAXに0を入れる操作を直接表す。文字の処理も、`mov al, [si]`で1文字を読み、`inc si`で次の文字へ進める操作に分ける。この2命令は方向フラグDFに依存しないため、`cld`も不要になる。`cmp al, 0`は文字を終端の0と比較し、`je`は等しい場合にジャンプする。

この章では文字を表示するだけで、マスク可能な外部割り込みを必要としないため、冒頭の`cli`で禁止したままにし、`sti`は使わない。この状態でも`int 0x10`は実行できる。停止ループでの`cli`も重複するため省略した。タイマーやキーボードの割り込みを使う段階では、割り込みを許可するか改めて検討する。

INT 10hの`AH=0Eh`は`AL`の1文字をテキスト画面へ出力する。ヌル終端まで繰り返すための文字列処理も、BIOS呼び出しの仕方も短い。割り込み時にCPU内部で何が起きるかは本編03章の範囲であり、ここではBIOS APIとして使う。

`times`で署名の前を埋めて合計512バイトにする。`dw 0xAA55`はリトルエンディアンでファイル末尾に`55 AA`を置く。

## ビルドして画面で確認

作業ディレクトリは第2章まで使う。以下はホームディレクトリに`tinypc-lite-work`を作った例である。

```sh
mkdir -p ~/tinypc-lite-work
cd ~/tinypc-lite-work
# ここに上のコードを boot.asm として保存する
nasm -f bin boot.asm -o boot.bin
wc -c < boot.bin
od -An -tx1 -j 510 -N 2 boot.bin
```

順に`512`と`55 aa`が出れば、サイズと署名が正しい。次に仮想フロッピーを作って起動する。

```sh
dd if=/dev/zero of=disk.img bs=512 count=2880
dd if=boot.bin of=disk.img conv=notrunc
qemu-system-i386 -boot a -drive format=raw,file=disk.img,if=floppy
```

QEMUの画面に`Booting...`が表示されれば成功。OSを起動していないため、文字列表示後は停止する。QEMUのウィンドウを閉じて終了する。

### 5分の演習：自分の文字列を表示する

`Booting...`を英数字の好きな文字列へ変え、`nasm`、2本の`dd`、QEMU起動をもう一度実行する。ソースを保存するだけではディスクイメージは更新されない。日本語の表示はこのBIOS出力例の対象外。

### コードを読むための最小限の知識

- レジスタはCPU内の小さな記憶領域。`AX`の上位8ビットが`AH`、下位8ビットが`AL`である。`mov`は値のコピー、`mov ax, 0`はAXに0を入れる。
- `DS:SI`は文字の場所。リアルモードでは物理アドレスを`DS × 16 + SI`で求める。ここではDSが0なので、SIの値がそのまま物理アドレスになる。
- `[si]`はDS:SIが指すメモリを表す。`mov al, [si]`でその場所の1バイトを読み、`inc si`でSIを1増やす。
- `SS:SP`はスタックの位置。`int`も戻り先などをスタックへ保存するので、第1章から初期化が必要。スタックは`0x7C00`から小さいアドレス側へ伸びる。
- `13, 10`は復帰と改行、末尾の`0`は自作ループの終端。`int 0x10`が文字列全体を処理するわけではない。
- `bits 16`と`org`はNASMへの指示であり、CPUが実行する命令ではない。`org`はデータをロードせず、CPUの実行モードも変更しない。
- `$-$$`はこのセクションの先頭から現在までのバイト数。`times 510-($-$$)`で署名前を埋める。コードとデータが510バイトを超えるとアセンブルに失敗する。

`hlt`はCPUを待機させる命令で、QEMUを終了する命令ではない。`cli`はマスク可能な外部割り込みを禁止するが、`int 0x10`のようなソフトウェア割り込みを禁止するものではない。
