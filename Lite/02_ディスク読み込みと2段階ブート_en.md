# 02 Disk Loading and Two-Stage Boot

A boot sector is limited to 512 bytes. We use the BIOS to load the next disk sector and then transfer control to it. Lite reads one sector from floppy CHS `0/0/2` (cylinder 0, head 0, sector 2) into `0000:8000`. This is LBA 1. This exercise does not implement LBA/CHS conversion or a loop for reading multiple sectors.

## Add disk loading to boot.asm

In the Chapter 1 working directory, replace `boot.asm` with the following code. The [completed version](../impl/lite/boot.asm) is also available for reference.

```asm
bits 16                       ; Tell NASM to generate 16-bit machine code (not a CPU instruction)
org 0x7C00                    ; Calculate labels assuming the code will be placed at RAM address 0x7C00

start:
    cli                       ; Disable maskable external interrupts while setting up the stack
    cld                       ; Clear the direction flag (DF); LODSB will then increment SI after reading
    xor ax, ax                ; Set AX to zero; XORing a value with itself produces zero
    mov ss, ax                ; Set SS to 0; the stack segment base is physical address 0
    mov sp, 0x7C00            ; Initial stack position; PUSH and INT use memory below this address
    mov ds, ax                ; Set DS to 0; physical addresses for data are DS×16 plus the offset
    mov es, ax                ; Set ES to 0, the segment used by the disk transfer destination ES:BX
    sti                       ; Enable external interrupts after setting SS:SP
    mov [boot_drive], dl      ; Save the boot drive number that BIOS passed in DL
    mov si, boot_message      ; Put the message's starting offset in SI; the value is not the character itself
    call puts                 ; Save the return address on the stack and call the string-printing routine

    mov ax, 0x0201            ; AH=02h selects disk read; AL=01h requests one sector
    mov bx, 0x8000            ; ES:BX=0000:8000; store the 512-byte sector in RAM starting at 0x8000
    mov cx, 0x0002            ; CH=0 selects cylinder 0; CL=2 selects sector 2 (sector numbering starts at 1)
    xor dh, dh                ; Set DH=0 to select floppy head 0
    mov dl, [boot_drive]      ; Restore the saved boot drive number in DL
    int 0x13                  ; Call the BIOS disk service; execution resumes at the next instruction afterward
    jc disk_error             ; If BIOS returns CF=1, branch to the disk-read error handler
    jmp 0x0000:0x8000         ; Set CS=0 and IP=0x8000 to start executing Stage 2

disk_error:
    mov si, error_message     ; Put the disk-read error message's starting offset in SI
    call puts                 ; Save the return address on the stack and call the string-printing routine
.halt:
    cli                       ; Disable maskable external interrupts (this does not disable INT instructions)
    hlt                       ; Put the CPU in a wait state; this does not exit QEMU
    jmp .halt                 ; Return to the halt loop and keep waiting

puts:
    lodsb                     ; Read one byte from DS:SI into AL; with DF=0, increment SI to the next byte
    test al, al               ; Check whether AL is zero by setting ZF; AL itself is unchanged
    jz .done                  ; If AL=0 (the string terminator), return to the caller
    mov ah, 0x0E              ; Select BIOS video function 0Eh to display the character in AL
    mov bx, 0x0007            ; BH=0 selects display page 0; BL=7 is used in graphics modes, not here
    int 0x10                  ; Call the BIOS video service; AH=0Eh displays the character in AL
    jmp puts                  ; Go back to process the next character (unlike CALL, JMP does not push a return address)
.done:
    ret                       ; Pop the return address saved by CALL and return to the caller

boot_message  db 'Booting...', 13, 10, 0 ; Boot message; 13 and 10 are carriage return and line feed, 0 ends the string
error_message db 'Disk read failed', 13, 10, 0 ; Store the disk-read error message as bytes
boot_drive    db 0            ; One-byte storage for the boot drive number (initial value 0)
times 510-($-$$) db 0         ; Pad with zeros to byte 510; $-$$ is the current section size
dw 0xAA55                     ; Store the two-byte signature; little-endian encoding puts 55 AA in the file
```

INT 13h with `AH=02h` reads one sector. `ES:BX` gives the destination. `CH` and `CL` specify the cylinder and sector, `DH` specifies the head (the upper two bits of CL hold the upper cylinder bits), and `DL` specifies the drive. We save the `DL` value supplied by BIOS at startup and restore it just before the call. If CF is set, the code stops with a read error. Retries and detailed error classification are outside the scope of this exercise.

## stage2.asm

In the same working directory, save the following as `stage2.asm`. The [completed version](../impl/lite/stage2.asm) is also available. The load address used by Stage 1 and NASM's address origin must both be `0x8000`.

```asm
bits 16                       ; Tell NASM to generate 16-bit machine code (not a CPU instruction)
org 0x8000                    ; Set the label origin to the RAM address 0x8000 where Stage 1 loads this code

start:
    cld                       ; Clear the direction flag (DF); LODSB will then increment SI after reading
    xor ax, ax                ; Set AX to zero; XORing a value with itself produces zero
    mov ds, ax                ; Set DS to 0; physical addresses for data are DS×16 plus the offset
    mov si, message           ; Put the message's starting offset in SI; DS:SI points to its first byte
.next:
    lodsb                     ; Read one byte from DS:SI into AL; with DF=0, increment SI to the next byte
    test al, al               ; Check whether AL is zero by setting ZF; AL itself is unchanged
    jz .halt                  ; If AL=0 (the string terminator), stop displaying and halt
    mov ah, 0x0E              ; Select BIOS video function 0Eh to display the character in AL
    mov bx, 0x0007            ; BH=0 selects display page 0; BL=7 is used in graphics modes, not here
    int 0x10                  ; Call the BIOS video service; AH=0Eh displays the character in AL
    jmp .next                 ; Return to the start of the loop to read the next character
.halt:
    cli                       ; Disable maskable external interrupts (this does not disable INT instructions)
.wait:
    hlt                       ; Put the CPU in a wait state; this does not exit QEMU
    jmp .wait                 ; If the CPU resumes, return to HLT and wait again

message db 'Hello from Stage 2!', 13, 10, 0 ; Stage 2 message; final 0 is not displayed and terminates the loop
```

Stage 2 also uses BIOS INT 10h, so it does not need UART. It inherits the stack initialized by Stage 1. Lite does not introduce crt0, BSS, or C `main`; those topics are covered in the full course chapter [[../05_リンカと複数ファイルカーネル]].

## Disk image and Makefile

Save the following as `Makefile` in the same working directory. Recipe lines must begin with a tab, not spaces.

The Lite-specific [`impl/lite/Makefile`](../impl/lite/Makefile) is independent of the full course Makefile.

<!-- markdownlint-disable MD010 -->
```make
NASM ?= nasm
QEMU ?= qemu-system-i386

.PHONY: all disk run clean
all: disk

boot.bin: boot.asm
	$(NASM) -f bin -o $@ $<

stage2.bin: stage2.asm
	$(NASM) -f bin -o $@ $<

disk: boot.bin stage2.bin
	test "$$(wc -c < stage2.bin)" -le 512
	dd if=/dev/zero of=disk.img bs=512 count=2880
	dd if=boot.bin of=disk.img conv=notrunc
	dd if=stage2.bin of=disk.img bs=512 seek=1 conv=notrunc

run: disk
	$(QEMU) -drive format=raw,file=disk.img,if=floppy

clean:
	rm -f boot.bin stage2.bin disk.img
```
<!-- markdownlint-enable MD010 -->

`make disk` creates a 1.44 MB disk image (2880 × 512 bytes). `seek=1` writes Stage 2 at offset 512 bytes, or LBA 1. The Makefile limits Stage 2 to one sector so its size matches the read performed by Stage 1.

```sh
cd ~/tinypc-lite-work
make clean
make run
```

QEMU normally opens a graphical window. The display should show these two lines in order:

```text
Booting...
Hello from Stage 2!
```

If only the first line appears, check the Stage 1 read-error message, Stage 2 size, `seek=1` versus CHS `0/0/2`, and the destination `0000:8000`.

## Separate disk placement from control transfer

| Content | Disk location | RAM location | Read by |
| :--- | :--- | :--- | :--- |
| Stage 1 | LBA 0, offset 0 | `0x7C00`–`0x7DFF` | SeaBIOS |
| Sector containing Stage 2 | LBA 1, offset 512 | `0x8000`–`0x81FF` | Requested by Stage 1 through INT 13h |

`int 0x13` copies data into RAM and returns. The following `jmp 0x0000:0x8000` executes the code that was loaded. A far jump sets both CS and IP. Stage 2's `org 0x8000` assumes the same memory placement when calculating label values.

This example does not search for a filename. There is no FAT filesystem or partition table; it relies on the convention that Stage 2 is in the second sector. Stage 2 is not an operating system. It is a small program that demonstrates transferring control to the next stage.

## Five-minute exercise: predict a placement mismatch

1. Confirm the normal output, then close QEMU.
2. In the Makefile, change only `seek=1` to `seek=2`. Predict which sector Stage 1 will read.
3. Run `make run`. `Hello from Stage 2!` will not appear after `Booting...`. The read itself may succeed, so `Disk read failed` is not necessarily displayed. Behavior after the CPU starts executing zeros or other unintended bytes is not guaranteed.
4. Close QEMU, restore `seek=1`, and run `make run` to confirm normal output.

Answer: Stage 2 moved to LBA 2, but Stage 1 still reads LBA 1. **Successfully reading a sector does not mean the intended program was read.**

If time allows, identify the three places to change when relocating Stage 2 in RAM: the read destination `ES:BX`, the far-jump target, and Stage 2's `org`. As a safe example, change all three to `0x9000`, verify the output, then restore them.

## Troubleshooting

| Symptom | Check |
| :--- | :--- |
| QEMU will not start | `qemu-system-i386 --version`; confirm a graphical environment is available |
| `Booting...` does not appear | Chapter 1 size and signature, writing the image, and boot device |
| `Disk read failed` appears | INT 13h failed; check the drive number and CHS values |
| Only the first line appears | Confirm `seek=1`, the load destination, jump target, and Stage 2 `org` agree |
| An old message appears | Close QEMU and rebuild; confirm you are not booting an image from another directory |
