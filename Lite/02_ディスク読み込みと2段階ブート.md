# 02 ディスク読み込みと2段階ブート

Boot Sectorは512バイトに限られる。そこで、ディスクの次のセクタをBIOSに読み込ませ、その内容へ制御を渡す。LiteではフロッピーのCHS `0/0/2`（シリンダ0、ヘッド0、セクタ2）を`0000:8000`へ1セクタだけ読む。これはLBA 1に対応する。LBA/CHS変換や複数セクタのループは実装しない。

## boot.asmへ読み込みを追加

第1章の作業ディレクトリで`boot.asm`を次のコードに置き換える。[完成版](../impl/lite/boot.asm)も参照できる。

```asm
bits 16                       ; NASMに16ビット用の機械語を生成させる指定（CPUへの命令ではない）
org 0x7C00                    ; RAMの0x7C00に配置される前提でラベルの値を計算する

start:
    cli                       ; マスク可能な外部割り込みを禁止する（INT命令は禁止されない）
    cld                       ; 方向フラグDFを0にする。以降のLODSBは読取り後にSIを1増やす
    xor ax, ax                ; AXを0にする。同じ値どうしのXORは0になる
    mov ss, ax                ; SS=0。スタックのセグメント基準を物理アドレス0にする
    mov sp, 0x7C00            ; スタックの初期位置。PUSHやINTで使用する領域はここから下へ伸びる
    mov ds, ax                ; DS=0。文字列や変数の物理アドレスはDS×16+オフセットで求める
    mov es, ax                ; ES=0。ディスク読込み先ES:BXのセグメント部分を設定する
    sti                       ; 外部割り込みを許可する。SS:SP設定後にBIOSサービスを利用する
    mov [boot_drive], dl      ; BIOSがDLで渡した起動ドライブ番号をメモリの変数へ保存する
    mov si, boot_message      ; SIに表示文字列の先頭位置を入れる（文字そのものではない）
    call puts                 ; 戻り先をスタックへ保存し、文字列表示処理putsへ移る

    mov ax, 0x0201            ; AH=02hはセクタ読込み機能、AL=01hは読み込むセクタ数
    mov bx, 0x8000            ; ES:BX=0000:8000。512バイトをRAMの0x8000から格納する
    mov cx, 0x0002            ; CH=0はシリンダ0、CL=2はセクタ2（セクタ番号は1から始まる）
    xor dh, dh                ; DH=0。フロッピーのヘッド0を指定する
    mov dl, [boot_drive]      ; 保存した起動ドライブ番号をDLへ戻し、読むドライブを指定する
    int 0x13                  ; BIOSのディスク処理を呼ぶ。読込み後は次の命令へ戻る
    jc disk_error             ; BIOSがCF=1を返した場合は読込み失敗としてエラー処理へ移る
    jmp 0x0000:0x8000         ; CS=0、IP=0x8000に設定し、読み込んだStage 2の実行を始める

disk_error:
    mov si, error_message     ; 読込み失敗を知らせる文字列の先頭位置をSIへ入れる
    call puts                 ; 戻り先をスタックへ保存し、文字列表示処理putsへ移る
.halt:
    cli                       ; マスク可能な外部割り込みを禁止する（INT命令は禁止されない）
    hlt                       ; CPUを待機させる。QEMUの終了命令ではない
    jmp .halt                 ; 停止処理へ戻り、待機を繰り返す

puts:
    lodsb                     ; DS:SIの1バイトをALへ読み、DF=0なのでSIを1増やして次の文字を指す
    test al, al               ; ALが0か調べてZFを設定する。ALの値は変えない
    jz .done                  ; AL=0（文字列終端）なら呼出し元へ戻る処理へ移る
    mov ah, 0x0E              ; BIOS画面出力の機能番号。ALに入っている1文字を出力する
    mov bx, 0x0007            ; BH=0で表示ページ0。BL=7はグラフィックスモード用で、ここでは使われない
    int 0x10                  ; BIOSの画面処理を呼ぶ。AH=0EhなのでALの1文字を表示する
    jmp puts                  ; putsの先頭へ戻って次の文字を処理する（CALLと違い戻り先は積まない）
.done:
    ret                       ; CALLがスタックに保存した戻り先を取り出し、呼出し元へ戻る

boot_message  db 'Booting...', 13, 10, 0 ; 起動メッセージ。13と10は復帰・改行、0は文字列終端
error_message db 'Disk read failed', 13, 10, 0 ; 読込み失敗時のメッセージをバイト列として配置する
boot_drive    db 0            ; 起動ドライブ番号を保存する1バイトの領域（初期値は0）
times 510-($-$$) db 0         ; 現在までの長さ($-$$)を510バイトから引き、残りを0で埋める
dw 0xAA55                     ; 署名を2バイトで配置する。リトルエンディアンなので順序は55 AA
```

INT 13h `AH=02h`で1セクタを読む。`ES:BX`は転送先、`CH`と`CL`でシリンダ・セクタ、`DH`でヘッドを指定する（CLの上位2ビットはシリンダ番号の上位分）、`DL`はドライブ番号である。BIOSが起動時に渡す`DL`を保存し、呼び出し直前に復元する。CFがセットされたときは読み込み失敗として止める。再試行や詳細なエラー分類は扱わない。

## stage2.asm

同じ作業ディレクトリに、次を`stage2.asm`として保存する。[完成版](../impl/lite/stage2.asm)も参照できる。Stage 1がロードする位置とNASMのアドレス基準を`0x8000`に合わせる。

```asm
bits 16                       ; NASMに16ビット用の機械語を生成させる指定（CPUへの命令ではない）
org 0x8000                    ; Stage 1が読み込むRAMの位置0x8000にラベルの基準を合わせる

start:
    cld                       ; 方向フラグDFを0にする。以降のLODSBは読取り後にSIを1増やす
    xor ax, ax                ; AXを0にする。同じ値どうしのXORは0になる
    mov ds, ax                ; DS=0。文字列や変数の物理アドレスはDS×16+オフセットで求める
    mov si, message           ; SIに表示文字列の先頭位置を入れ、DS:SIで先頭の文字を指す
.next:
    lodsb                     ; DS:SIの1バイトをALへ読み、DF=0なのでSIを1増やして次の文字を指す
    test al, al               ; ALが0か調べてZFを設定する。ALの値は変えない
    jz .halt                  ; AL=0（文字列終端）なら表示を終え、停止処理へ移る
    mov ah, 0x0E              ; BIOS画面出力の機能番号。ALに入っている1文字を出力する
    mov bx, 0x0007            ; BH=0で表示ページ0。BL=7はグラフィックスモード用で、ここでは使われない
    int 0x10                  ; BIOSの画面処理を呼ぶ。AH=0EhなのでALの1文字を表示する
    jmp .next                 ; 次の文字を読み出すため、文字列処理ループの先頭へ戻る
.halt:
    cli                       ; マスク可能な外部割り込みを禁止する（INT命令は禁止されない）
.wait:
    hlt                       ; CPUを待機させる。QEMUの終了命令ではない
    jmp .wait                 ; 待機から復帰した場合も、HLTへ戻って待機を繰り返す

message db 'Hello from Stage 2!', 13, 10, 0 ; Stage 2の文字列。最後の0は表示せず、ループを終える目印にする
```

Stage 2もBIOS INT 10hを利用するため、UARTは不要である。Stage 2はStage 1が初期化したスタックを引き継ぐ。Liteではcrt0、BSS、Cの`main`を導入しない。これらを加える段階は本編[[../05_リンカと複数ファイルカーネル]]に分ける。

## ディスクイメージとMakefile

同じ作業ディレクトリに、以下を`Makefile`として保存する。コマンド行の先頭は空白ではなくタブにする。

`impl/lite/Makefile`は[こちら](../impl/lite/Makefile)に置くLite専用のMakefileで、本編のMakefileを呼び出さない。

<!-- markdownlint-disable MD010 -->
```make
NASM ?= nasm
QEMU ?= qemu-system-i386

.PHONY: all disk run clean
all: disk

boot.bin: boot.asm
	$(NASM) -f bin -o $@ $<

stage2.bin: stage2.asm
	$(NASM) -f bin -o $@ $<

disk: boot.bin stage2.bin
	test "$$(wc -c < stage2.bin)" -le 512
	dd if=/dev/zero of=disk.img bs=512 count=2880
	dd if=boot.bin of=disk.img conv=notrunc
	dd if=stage2.bin of=disk.img bs=512 seek=1 conv=notrunc

run: disk
	$(QEMU) -drive format=raw,file=disk.img,if=floppy

clean:
	rm -f boot.bin stage2.bin disk.img
```
<!-- markdownlint-enable MD010 -->

`make disk`で1.44MB（2880×512バイト）のイメージを作る。`seek=1`は512バイト先、つまりLBA 1にStage 2を書く指定である。Stage 2を1セクタ以内に制限し、読み込みサイズとの不一致を防ぐ。

```sh
cd ~/tinypc-lite-work
make clean
make run
```

標準はGUI起動である。画面に次の2行が順に表示される。

```text
Booting...
Hello from Stage 2!
```

1行目の後で止まるときは、Stage 1の読み込み失敗表示、Stage 2のサイズ、`seek=1`とCHS `0/0/2`、読み込み先`0000:8000`を確かめる。

## 配置と制御の移動を分けて読む

| 内容 | ディスク上の位置 | RAM上の位置 | 読む担当 |
| :--- | :--- | :--- | :--- |
| Stage 1 | LBA 0、先頭から0バイト | `0x7C00`〜`0x7DFF` | SeaBIOS |
| Stage 2を含むセクタ | LBA 1、先頭から512バイト | `0x8000`〜`0x81FF` | Stage 1がINT 13hで依頼 |

`int 0x13`はデータをRAMへコピーして戻る。読み込んだコードを実行するのは、その次の`jmp 0x0000:0x8000`である。far jumpはCSとIPの両方を設定する。Stage 2の`org 0x8000`も同じ配置を前提にラベルの値を計算する。

ここではファイル名を検索していない。FATもパーティションテーブルもなく、「2番目のセクタにStage 2がある」という約束だけで読む。Stage 2はOSではなく、次段へ制御を渡せたことを示す小さなプログラムである。

## 5分の演習：配置をずらして予測する

1. まず正常表示を確認してQEMUを閉じる。
2. Makefileの`seek=1`だけを`seek=2`に変える。Stage 1はどのセクタを読むか予測する。
3. `make run`を実行する。`Booting...`の後にStage 2の文字列が出なくなる。読み込み自体は成功しうるため、`Disk read failed`が出るとは限らない。ゼロなどを命令として実行した後の挙動は保証できない。
4. QEMUを閉じ、`seek=1`に戻して`make run`で正常表示を確認する。

答え：Stage 2はLBA 2へ移ったが、Stage 1はLBA 1を読み続けている。**ディスクから読めたことと、正しいプログラムを読めたことは別**である。

余裕があれば、RAM上の配置を変える場合に修正する3箇所を挙げる。答えは読み込み先`ES:BX`、far jumpの実行先、Stage 2の`org`。実行するなら安全な別領域の例として`0x9000`へ3箇所とも変え、動作確認後に戻す。

## 表示されないとき

| 症状 | 確認すること |
| :--- | :--- |
| QEMUを起動できない | `qemu-system-i386 --version`、GUIが使える環境か |
| `Booting...`も出ない | 第1章のサイズ・署名、イメージへの書込み、起動媒体 |
| `Disk read failed` | INT 13hが失敗した。ドライブ番号とCHS指定を確認 |
| 1行目だけ出る | `seek=1`、読み込み先、ジャンプ先、Stage 2の`org`が一致するか |
| 編集前の文字が出る | QEMUを閉じて再ビルドしたか、別ディレクトリのイメージを起動していないか |

複数セクタ、LBA拡張、汎用ローダーは本編[[../04_ディスク読み込みと2段階ブート]]で扱う。
