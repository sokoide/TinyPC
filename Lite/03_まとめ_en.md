# 03 Summary

## Boot path

```text
CPU Reset
  → SeaBIOS
  → Load and run disk LBA 0 at 0x7C00
      ├─ INT 10h: "Booting..."
      ├─ INT 13h: read one sector from CHS 0/0/2 into 0000:8000
      └─ far jump to 0000:8000
          └─ INT 10h: "Hello from Stage 2!"
```

## Explain it in your own words

- What sector size, load address, and signature does the BIOS boot process expect here?
- Where on disk is Stage 2 stored, and at what address does it run?
- What do `INT 10h` and `INT 13h` do?
- Why save the boot drive number from `DL` and pass it to INT 13h?
- How do Stage 2's `org 0x8000` and the far jump to `0000:8000` relate?

This course covers the boot chain. IVT internals, detailed stack behavior, BSS, and C `main` are outside its scope.

## Check your answers

1. For this virtual floppy boot, the first 512 bytes are loaded at physical address `0x7C00`, and the final two bytes are `55 AA`. The program and data have 510 bytes before the signature.
2. Stage 2 is stored at LBA 1 (CHS 0/0/2), and Stage 1 loads it at `0x8000`. A disk sector number and a RAM address are different things.
3. INT 10h function `AH=0Eh` displays one character. INT 13h function `AH=02h` reads disk sectors. These are services provided by the BIOS.
4. Save and reuse the `DL` value passed by BIOS so the code reads from the same drive it booted from.
5. `org` provides the address assumption NASM uses to calculate labels. The far jump changes where the CPU executes. The load destination must agree with both.

To meet the learning objective, label each arrow in `SeaBIOS → Stage 1 → Stage 2` with **who reads from where on disk, where it loads the data in RAM, and where it transfers execution**.

## Technical assumptions and references

This implementation assumes real-mode BIOS services and a 1.44 MB virtual floppy. It does not cover disk-read retries, filesystems, or installation on physical hardware.

- [NASM manual: `bin` and `ORG`](https://www.nasm.us/doc/nasm09.html) — meaning of `org` and flat binary output.
- [SeaBIOS source: `boot.c`](https://github.com/coreboot/seabios/blob/master/src/boot.c) — loading the first sector through `boot_disk` and transferring control through `call_boot_entry`. Signature checks for floppy boot have configuration-dependent exceptions, so removing the signature does not always guarantee boot failure.
- [SeaBIOS: execution phases](https://qemu.googlesource.com/seabios/+/refs/tags/rel-1.17.0/docs/Execution_and_code_flow.md) — the flow from initialization to the boot phase.
